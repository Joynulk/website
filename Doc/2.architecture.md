# 2. Architecture

## ধরন
ছোট দোকানের জন্য আলাদা backend সার্ভার ছাড়া একটা সরল গঠন। যে লজিক বিশ্বাসযোগ্য হতে হবে (দাম হিসাব, অর্ডার তৈরি) সেটা database-এর ভেতরে থাকে। ব্রাউজার শুধু দেখায় আর অনুরোধ পাঠায়।

```
ক্রেতা / admin (ব্রাউজার)
   -> static পেজ (HTML + mela.js)
   -> Supabase REST API (PostgREST)
   -> Postgres (Row Level Security + functions)
```

## Module ও যেখানে আছে
| Module | এখন কোথায় | অবস্থা |
|---|---|---|
| Product catalogue | `products`, `categories` টেবিল; `Mela.load()` | আছে |
| Cart | ব্রাউজারের localStorage (`mela_cart`) | আছে |
| Wishlist | localStorage (`mela_wish`) | আছে (ব্রাউজারে) |
| Checkout ও Orders | `place_order` function, `orders`, `order_items` | আছে |
| Pricing | `place_order`-এর ভেতরে (ফি, উপহার প্যাক) | আছে |
| Identity (ক্রেতা) | এখন শুধু ব্রাউজারে সংরক্ষিত নাম-ঠিকানা | Supabase Auth আসবে (ধাপ C) |
| Admin operations | `admins` টেবিল ও `is_admin()` তৈরি, UI নেই | ধাপ D |
| Inventory | `products.stock` কলাম আছে, কোথাও যাচাই বা কমানো হয় না | ধাপ E |
| Payments, Shipping tracking, Returns, Notifications | নেই | ধাপ F |

## ফাইল ও দায়িত্ব
| ফাইল | কাজ |
|---|---|
| `index.html` | হোম পেজ, নিজস্ব inline CSS, 3D ক্যাটাগরি রিং, product morph |
| `shop.html`, `product.html`, `wishlist.html`, `cart.html`, `order-placed.html`, `account.html` | অন্য পেজ, `mela.css` ব্যবহার করে |
| `mela.js` | পণ্য লোড, Supabase কল, cart/wishlist/order সহায়ক, header/footer |
| `supabase/schema.sql` | শুরুর database schema |

## ডেটা প্রবাহ: অর্ডার
1. ক্রেতা cart ভরে checkout ফর্ম পূরণ করে।
2. ব্রাউজার `place_order` কল করে, শুধু পণ্যের id, সংখ্যা আর উপহার প্যাক আছে কি না পাঠায়। দাম পাঠায় না।
3. Database পণ্য খুঁজে দাম, ডেলিভারি ফি আর মোট হিসাব করে অর্ডার ও আইটেম এক ধাপে লিখে।
4. ব্রাউজার অর্ডার নম্বর ও মোট ফেরত পায়, cart খালি করে, confirmation পেজে যায়।

## কখন আলাদা সার্ভার (Edge Function) লাগবে
যে কাজে গোপন key লাগে, সেটা ব্রাউজারে করা যাবে না। যেমন পেমেন্ট gateway-এর webhook যাচাই, SMS পাঠানো। এগুলোর জন্য Supabase Edge Function ব্যবহার হবে (ধাপ F)। তার আগে লাগবে না।

## সীমা ও ঝুঁকি
- **Region:** Supabase project আছে `ap-southeast-2` (সিডনি)। বাংলাদেশ থেকে একটু বেশি দেরি হতে পারে। Region পরে বদলানো যায় না, বদলাতে হলে নতুন project লাগবে। মাপার পর দরকার মনে হলে সিদ্ধান্ত নেব।
- **Vendor lock-in:** ডেটা সাধারণ Postgres-এ, সরানো সম্ভব। `place_order`-এর মতো function আর RLS নিয়ম সঙ্গে নিয়ে যেতে হবে।
- **খরচ ও সীমা:** আপনার Supabase প্ল্যান ও তার সীমা (storage, bandwidth, প্রজেক্ট বিরতি) dashboard-এ দেখে নিন। এখানে যাচাই করা হয়নি।
- **Hosting:** README-তে GitHub Pages-এর কথা আছে। সত্যিই চালু করা হয়েছে কি না এখানে যাচাই হয়নি।
- cart, wishlist, saved ঠিকানা ব্রাউজারে থাকে, ডিভাইস বদলালে হারায়। লগইন (ধাপ C) এর সমাধান করবে।
