# 12. নতুন অর্ডারের Telegram বিজ্ঞপ্তি (ধাপ F)

শেষ হালনাগাদ: 2026-11-01

**অবস্থা:** কাজ করছে। মালিক bot বানিয়ে token ও chat id Vault-এ বসিয়েছেন; টেস্ট বার্তা (T1) ও আসল অর্ডারের বার্তা (T2, অর্ডার M000003) Telegram-এ এসেছে (মালিকের স্ক্রিনশট 2026-11-01, আর database-এ Telegram-এর উত্তর HTTP 200 দেখা গেছে)। T3-T5 বাকি।

## আপনার সিদ্ধান্ত
| বিষয় | সিদ্ধান্ত |
|---|---|
| নতুন অর্ডার এলে মালিককে জানানো | Telegram bot |
| অনলাইন পেমেন্ট | এখন শুধু COD। merchant অ্যাকাউন্ট পেলে পরে |

## কীভাবে কাজ করে
1. অর্ডার সম্পূর্ণ হলে (আইটেম লেখা শেষ, মোট বসেছে) database trigger `orders_notify` চালু হয়।
2. Trigger Supabase Vault থেকে bot token ও chat id পড়ে `pg_net` দিয়ে Telegram-এর `sendMessage` ডাকে। অ্যাসিঙ্ক, তাই অর্ডার দেওয়া ধীর হয় না।
3. Telegram বা Vault-এর সমস্যায় অর্ডার আটকাবে না। তথ্য (token/chat id) না থাকলে বার্তা চুপচাপ বাদ যায়।

## বার্তায় কী যায়
```
🛒 নতুন অর্ডার M000003
• জামদানি শাড়ি × 1
মোট: ৳4800 (ক্যাশ অন ডেলিভারি)
নাম, ফোন ও ঠিকানা দেখতে admin panel খুলুন।
```
(এটা মালিকের আসল টেস্ট অর্ডারের বার্তা, তিনি পরে অর্ডারটি বাতিল করেছেন, সত্যিকারের ক্রেতার অর্ডার নয়।)
ক্রেতার নাম, ফোন ও ঠিকানা বার্তায় যায় না, কারণ Telegram একটি তৃতীয় পক্ষ ও গোপনীয় তথ্য সেখানে না নিয়ে গেলে ঝুঁকি কম। ফোন নম্বর আসা দরকার মনে হলে বলবেন, `build_order_message` function বদলাব।

## সেটআপ (আপনি করেছেন; নতুন করতে হলে এই ধাপগুলো)
**bot token কখনো চ্যাটে (আমাকেও না), repo-তে বা কোডে দেবেন না। শুধু নিচের ধাপ 4-এর SQL-এ।**
1. Telegram-এ `@BotFather` খুলুন -> `/newbot` -> নাম ও username দিন। সে একটা token দেবে (মুদ্রণে সংখ্যা, `:`, তারপর অক্ষর)।
2. নতুন bot-এর চ্যাট খুলে **Start** চাপুন আর একটা বার্তা পাঠান (না পাঠালে bot আপনাকে বার্তা পাঠাতে পারবে না)।
3. নিজের ব্রাউজারে `https://api.telegram.org/bot<আপনার-token>/getUpdates` খুলুন। উত্তরে `"chat":{"id":123456789` দেখলে ওই সংখ্যাটাই chat id। (লিংকটি কাউকে পাঠাবেন না, কারণ তাতে token আছে।)
4. Supabase -> SQL Editor-এ চালান:
```sql
select vault.create_secret('আপনার-bot-token', 'telegram_bot_token');
select vault.create_secret('আপনার-chat-id', 'telegram_chat_id');
```
5. একই জায়গায় চালান `select send_test_telegram();`। Telegram-এ টেস্ট বার্তা আসার কথা। না এলে: `select status_code, content from net._http_response order by id desc limit 1;` দিয়ে কারণ দেখুন।
6. সাইটে একটা অর্ডার দিন (পরে admin থেকে বাতিল করুন)। বার্তা আসার কথা।

ভুল token বা chat id বসালে পুরনোটা মুছে আবার বসান:
```sql
delete from vault.secrets where name in ('telegram_bot_token','telegram_chat_id');
```
বন্ধ করতে চাইলেও এই লাইন (বার্তা আসা বন্ধ হবে, অর্ডার থামবে না)।

## নিরাপত্তা ও সীমা
- Token ফাঁস হলে BotFather-এ `/revoke` দিয়ে নতুন token নিন ও Vault-এ বদলান।
- বার্তা পাঠানোর চেষ্টা অ্যাসিঙ্ক ও একবারই। Telegram ডাউন হলে বার্তা হারিয়ে যাবে, আবার চেষ্টা করবে না। তাই admin panel মাঝে মাঝে খুলে দেখা দরকার।
- Token ও chat id শুধু একজন প্রাপকের। কয়জনকে জানাতে চাইলে Telegram group বানিয়ে bot যোগ করে ওই group-এর chat id দিন।
- Token Telegram-এর এপিআই ঠিকানায় যুক্ত হয়ে পাঠানো হয়, তাই Supabase-এর ভেতরের HTTP রিকোয়েস্ট তালিকায় (`net` schema) কিছুক্ষণ থাকতে পারে। এখানে শুধু আপনি (project owner) প্রবেশ করতে পারেন। বিস্তারিত রাখার সময় মাপা হয়নি।
- ফাঁকা বাতিল অর্ডার, অবস্থা বদলের বিজ্ঞপ্তি এখন নেই। শুধু "নতুন অর্ডার" আসে।
- ক্রেতাকে SMS/ইমেইল পাঠানো এখন নেই।
