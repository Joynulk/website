# 10. Admin panel (ধাপ D)

শেষ হালনাগাদ: 2026-10-29

**অবস্থা:** `admin.html` কোড `main`-এ আছে। Database-এর নিয়ম Supabase-এ চালিয়ে যাচাই হয়েছে (নিচে)। মালিক নিজে ব্রাউজারে X1-X11 চালিয়েছেন (ফল নিচের টেবিলে); X7 তে একটা সমস্যা পাওয়া গেছে (ব্যাখ্যা টেবিলের পরে), X12 বাকি।

## প্রথম admin বানানো
1. `account.html`-এ আপনার ইমেইল-পাসওয়ার্ডে সাইন আপ করুন (ইমেইল যাচাই বন্ধ থাকতে হবে, [9.auth.md](9.auth.md))।
2. `admin.html` খুলুন। "অনুমতি নেই" পেজে আপনার ইমেইলসহ একটা SQL দেখাবে।
3. সেটা Supabase -> SQL Editor-এ একবার চালান।
4. `admin.html` রিফ্রেশ করুন।

## অর্ডার নিয়ম (database trigger `orders_guard`, migration 003)
| আগের অবস্থা | যেতে পারে |
|---|---|
| pending | shipped, cancelled |
| shipped | delivered, cancelled |
| delivered, cancelled | কোথাও না (শেষ) |

- অর্ডার তৈরির পর `status` ছাড়া আর কোনো কলাম (নাম, ফোন, ঠিকানা, দাম, user_id) বদলানো যায় না। এটা সবার ক্ষেত্রে প্রযোজ্য, admin সহ।
- বাতিল হলে অর্ডারের পণ্য stock-এ ফেরত আসে (migration 004, [11.orders-safety.md](11.orders-safety.md))।
- প্রতিটি অবস্থা বদল `order_events` টেবিলে লগ হয় (কোন অর্ডার, কী থেকে কী, কে, কখন)। শুধু admin পড়তে পারে। এখন admin panel-এ এই লগ দেখানো হয় নি, Supabase Table Editor-এ দেখা যাবে।
- ঠিকানার ভুল সংশোধন দরকার হলে (শুধু মালিক, সাবধানে) Supabase SQL Editor-এ:
```sql
alter table orders disable trigger orders_guard;
update orders set address = 'নতুন ঠিকানা' where id = 'M000001';
alter table orders enable trigger orders_guard;
```
(শেষে `enable` করা ভুলবেন না।)

## নিরাপত্তা
- `admin.html` লুকানো নয় (সবাই পেজটা খুলতে পারবে, `noindex` আছে)। সুরক্ষা আসলে database-এ: `admins` টেবিল + Row Level Security + trigger। পেজের "admin কি না" যাচাই শুধু সুবিধার জন্য।
- নাম, ঠিকানা, পণ্যের নাম সব জায়গায় `esc()` দিয়ে দেখানো হয় (সাইটেও)। রঙের মান `#rrggbb` না হলে সোনালি ধরা হয়।
- Token এখনো localStorage-এ ([Boundary.md](Boundary.md))। Admin অ্যাকাউন্টে শক্ত পাসওয়ার্ড রাখুন, অচেনা লিংক খুলবেন না।

**X7-এর কারণ (2026-10-29, database দেখে বের করা):** আপনার দুটো অর্ডার আলাদা বাস্তবতায় ছিল। M000001 (pending -> shipped -> delivered) লগইন ছাড়া দেওয়া, তাই অ্যাকাউন্টে যুক্ত নয় (`user_id` খালি)। অ্যাকাউন্ট পেজ তখন ব্রাউজারের নিজস্ব কপি দেখায়, যার অবস্থা অর্ডারের সময়ের "প্রক্রিয়াধীন" থেকে কখনো বদলায় না। M000002 (pending -> cancelled) লগইন অবস্থায় দেওয়া (`user_id` ভরা), তাই সার্ভার থেকে সত্যিকারের "বাতিল" অবস্থা এসেছে। অর্থাৎ অবস্থা বদলানোর ব্যবস্থা ঠিক আছে; সমস্যা হলো লগইন ছাড়া দেওয়া অর্ডারের অবস্থা ক্রেতা পান না (জানা সীমা, [4.database.md](4.database.md))। সমাধান পরের পদক্ষেপে।
