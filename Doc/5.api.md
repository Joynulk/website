# 5. API

আলাদা backend সার্ভার নেই। ব্রাউজার সরাসরি Supabase REST API-কে ডাকে। Row Level Security আর database function ঠিক করে কে কী পারবে।

**Base URL:** `https://gjawsgadcwqlohvfakzp.supabase.co/rest/v1/`
**Header:** `apikey: <publishable key>` (`mela.js`-এ আছে। এটা প্রকাশ্য হওয়ার জন্যই বানানো)। `Content-Type: application/json`। ক্রেতা লগইন করা থাকলে সাথে `Authorization: Bearer <তার token>` যায়।

> `service_role` বা secret key কখনো ব্রাউজারের কোডে বা repo-তে যাবে না।

লগইনের endpoint (`/auth/v1/`) আলাদা: [9.auth.md](9.auth.md)।

## বর্তমান endpoint

### ক্যাটাগরি পড়া
`GET categories?select=id,name,emoji,color&order=sort`
উত্তর: ক্যাটাগরির তালিকা (JSON array)।

### পণ্য পড়া
`GET products?select=id,name,category_id,price,emoji,description&active=eq.true&order=id`
উত্তর: সক্রিয় পণ্যের তালিকা।

### অর্ডার করা
`POST rpc/place_order`

Request:
```json
{
  "p_name": "রহিম উদ্দিন",
  "p_phone": "01712345678",
  "p_address": "বাড়ি ১২, রোড ৩, ধানমন্ডি, ঢাকা",
  "p_items": [
    { "id": 1, "qty": 1, "gift": true },
    { "id": 14, "qty": 2 }
  ]
}
```
Success: `{ "id": "M000001", "total": 5040 }`

নিয়ম:
- নাম কমপক্ষে 2 অক্ষর, ঠিকানা কমপক্ষে 5 অক্ষর, ফোন `01[3-9]` দিয়ে শুরু 11 অঙ্ক।
- `p_items` খালি হতে পারবে না। প্রতিটি `qty` 1 থেকে 20। পণ্য থাকতে ও `active` হতে হবে।
- Request-এ দাম পাঠালেও সেটা গ্রাহ্য হয় না।

Error হলে HTTP status সফল (2xx) হয় না, body-তে JSON আছে যার `message` ক্ষেত্রে কারণ থাকে:

| message | মানে |
|---|---|
| `invalid details` | নাম, ফোন বা ঠিকানা ঠিক নেই |
| `empty cart` | `p_items` খালি বা array নয় |
| `product not found` | পণ্য নেই বা বন্ধ |
| `bad quantity` | সংখ্যা 1-20 এর বাইরে |

Frontend শুধু সাধারণ বার্তা দেখায়, ভেতরের message ক্রেতাকে দেখায় না (শুধু `product not found` হলে কার্ট থেকে সরানোর কথা বলে)।

### নিজের অর্ডার দেখা (লগইন থাকলে)
`GET orders?select=id,total,status,created_at,order_items(name,emoji,unit_price,qty)&order=created_at.desc&limit=50`
লগইন করা ক্রেতার token দিলে RLS শুধু তার নিজের সারিগুলো দেয়। token ছাড়া খালি তালিকা আসার কথা।

## Admin endpoint (শুধু admin-এর token দিয়ে কাজ করে, না হলে RLS আটকায়)
বিস্তারিত ও পরীক্ষা: [10.admin.md](10.admin.md)।

| কাজ | কল |
|---|---|
| admin কি না | `POST rpc/is_admin` -> `true`/`false` |
| সব অর্ডার | `GET orders?select=...,order_items(...)&order=created_at.desc&limit=100` (+ `&status=eq.<মান>`) |
| অবস্থা বদল | `PATCH orders?id=eq.<id>` `{status}` + header `Prefer: return=representation`। অবৈধ পথে error `invalid status change`, অন্য কলাম বদলালে `only status can change` |
| সব পণ্য (লুকানোসহ) | `GET products?select=id,name,category_id,price,emoji,description,stock,active&order=id` |
| পণ্য যোগ / সম্পাদনা | `POST products` / `PATCH products?id=eq.<id>` |
| ক্যাটাগরি যোগ / সম্পাদনা | `POST categories` / `PATCH categories?id=eq.<id>` |

ক্ষেত্রে `Prefer: return=representation` দিলে ফলাফল সারি ফেরত আসে। খালি array মানে RLS কাজটি আটকেছে (পেজ এটাকে ব্যর্থতা ধরে)।

## পেজিনেশন
এখন পণ্য কম, সব একসাথে আসে। পণ্য 200-র বেশি হলে `limit` ও `offset` (বা `Range` header) যোগ করা হবে। ক্রেতার অর্ডার তালিকায় `limit=50`, admin-এ `limit=100` (পেজিনেশন নেই)।
