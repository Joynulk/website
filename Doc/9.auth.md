# 9. Customer Login (ধাপ C)

শেষ হালনাগাদ: 2026-10-30

**অবস্থা:** কোড `main`-এ আছে, মালিক ব্রাউজারে সাইন আপ, লগইন ও অর্ডার ইতিহাস দেখেছেন (M000002 লগইন অবস্থায় দেওয়া ও নিজের সারিতে এসেছে)। লগইন ও নতুন অ্যাকাউন্ট এখন আলাদা পেজ (নিচে দেখুন); এই পরিবর্তনের পরীক্ষা বাকি। পাসওয়ার্ড রিসেট ও dashboard সেটিং যাচাই হয়নি।

## আপনার সিদ্ধান্ত
| বিষয় | সিদ্ধান্ত |
|---|---|
| লগইন পদ্ধতি | ইমেইল + পাসওয়ার্ড |
| লগইন ও নতুন অ্যাকাউন্ট | আলাদা পেজ: `login.html`, `signup.html` |
| লগইন ছাড়া অর্ডার | চলবে (guest) |
| ইমেইল যাচাই | এখন বন্ধ, launch-এর আগে চালু |

## পেজগুলো
| পেজ | কাজ |
|---|---|
| `login.html` | ইমেইল + পাসওয়ার্ডে লগইন, "পাসওয়ার্ড ভুলে গেছেন?", নিচে "নতুন অ্যাকাউন্ট" লিংক, পাসওয়ার্ড দেখানোর টিক |
| `signup.html` | ইমেইল + পাসওয়ার্ড (দুইবার লিখতে হয়, মিলতে হবে), নিচে "লগইন" লিংক |
| `account.html` | লগইন না থাকলে দুটো বাটন (লগইন / নতুন অ্যাকাউন্ট); লগইন থাকলে ইমেইল, লগ আউট, ডেলিভারির তথ্য, অর্ডার ইতিহাস। পাসওয়ার্ড রিসেটের লিংকও এখানে আসে |

লগইন/সাইন আপের পর যে পেজে যাওয়া হবে তা `?next=` দিয়ে বলা যায় (যেমন `login.html?next=cart.html`)। শুধু নিচের সাইটের নিজস্ব পেজ গ্রহণ হয় (account, cart, admin, shop, index, wishlist), না হলে `account.html`। লগইন করা অবস্থায় লগইন/সাইন আপ পেজ খুললে সরাসরি ওই পেজে চলে যায়। `admin.html`-এর নিজস্ব লগইন ফর্ম আগের মতোই আছে।

## কীভাবে কাজ করে
- Supabase Auth, আলাদা library ছাড়াই। `mela.js` সরাসরি `/auth/v1/...` ডাকে।
- Session ব্রাউজারের localStorage-এ (`mela_session`: access token, refresh token, মেয়াদ, ইমেইল)। মেয়াদ শেষ হওয়ার এক মিনিট আগে নিজে নিজে নতুন token নেয় (একসাথে একাধিক অনুরোধ এলে একটাই refresh)।
- লগইন থাকলে সব Supabase কলে `Authorization: Bearer <token>` যায়। তাই `place_order` অর্ডারে `user_id` বসায়, আর RLS ক্রেতাকে শুধু তার নিজের অর্ডার দেখায়।
- ডেলিভারির তথ্য (নাম, ফোন, ঠিকানা) অ্যাকাউন্টের `user_metadata`-তে (`full_name`, `mobile`, `address`)। আলাদা টেবিল নেই। এটা শুধু ফর্ম ভরানোর জন্য ঠিক। ক্রেতা নিজে এই ডেটা বদলাতে পারে, তাই অর্ডারের আসল তথ্যের উৎস `orders` টেবিল।
- লগইনের আগে দেওয়া guest অর্ডার অ্যাকাউন্টে যুক্ত হয় না। সেগুলো অ্যাকাউন্ট পেজে "লগইন ছাড়া দেওয়া অর্ডার" হিসেবে ব্রাউজারের তালিকা থেকে আসে, যার অবস্থা আপডেট হয় না (সিদ্ধান্ত: ধাপ F-এ বদলাবে, [10.admin.md](10.admin.md) X7)।
- লগ আউটে session ও ব্রাউজারে সংরক্ষিত ডেলিভারির তথ্য মুছে যায় (শেয়ার করা ডিভাইসের জন্য)।
- পাসওয়ার্ড আমরা কখনো রাখি না। এটা Supabase Auth সামলায়।

## আপনার করণীয় (Supabase dashboard, সবগুলো আমি নিজে বদলাতে পারি না)
মেনুর নাম Supabase বদলাতে পারে, না পেলে dashboard-এর search ব্যবহার করুন।
1. **Authentication -> Sign In / Providers -> Email**: "Confirm email" **বন্ধ** (আপনার সিদ্ধান্ত। না করলে সাইন আপের পর লগইন হবে না, ইমেইলের লিংক লাগবে)।
2. **Authentication -> URL Configuration**: Site URL = আপনার সাইটের আসল ঠিকানা। Redirect URLs-এও সেটা দিন। পাসওয়ার্ড রিসেটের লিংক এখানে আসবে।
3. পাসওয়ার্ডের ন্যূনতম দৈর্ঘ্য 8 করুন (Supabase-এর ডিফল্ট কম)। সাইটের ফর্ম 8 চায়।
4. Launch-এর আগে: "Confirm email" চালু + নিজস্ব SMTP (Supabase-এর বিল্ট-ইন ইমেইলে ঘণ্টায় সীমিত সংখ্যায় পাঠানো যায়, সীমা আপনার প্ল্যানে দেখে নিন)।

## Auth endpoint (`/auth/v1/`)
| কাজ | কল |
|---|---|
| সাইন আপ | `POST signup` `{email, password}` |
| লগইন | `POST token?grant_type=password` `{email, password}` |
| Token নবায়ন | `POST token?grant_type=refresh_token` `{refresh_token}` |
| লগ আউট | `POST logout` (Bearer token) |
| পাসওয়ার্ড রিসেট ইমেইল | `POST recover` `{email}` |
| নতুন পাসওয়ার্ড | `PUT user` `{password}` (রিসেট লিংকের token দিয়ে) |
| ডেলিভারির তথ্য সংরক্ষণ | `PUT user` `{data:{full_name, mobile, address}}` |

রিসেট লিংক Site URL-এ আসে `#access_token=...&type=recovery` সহ। `mela.js` সেটাকে স্বয়ংক্রিয়ভাবে `account.html`-এ পাঠায়।

## নিরাপত্তা নোট
- Token localStorage-এ থাকে। সাইটে XSS হলে চুরি যেতে পারে। পণ্যের নাম/বিবরণ এখন `esc()` দিয়ে দেখানো হয় ([6.security.md](6.security.md)), তবু token localStorage-এ থাকার সীমাটা থাকে ([Boundary.md](Boundary.md))।
- ভুয়া ইমেইল দিয়ে সাইন আপ থেকে রক্ষা ইমেইল যাচাই চালু না হওয়া পর্যন্ত থাকবে। অর্ডার করার জন্য ইমেইল লাগে না, তাই ক্ষতি সীমিত।
- সাইন আপ/লগইনের গতি সীমা Supabase Auth-এর নিজস্ব নিয়মে চলে। `place_order`-এ ফোন-ভিত্তিক spam সীমা আছে ([11.orders-safety.md](11.orders-safety.md))।
- ফোন OTP নেওয়া হয়নি: SMS খরচ ও আলাদা provider লাগে। পরে দরকার হলে ভাবা যাবে।
