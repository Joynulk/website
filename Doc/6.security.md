# 6. Security

চিহ্ন: ✅ আছে (কোডে বা database-এ), ⚠️ আংশিক বা পরীক্ষা বাকি, ❌ নেই।

"আছে" মানে কোডে বা schema-তে বসানো হয়েছে। বাস্তবে চালিয়ে পরীক্ষা এখনো হয়নি ([7.testing.md](7.testing.md))।

## অ্যাক্সেস ও অনুমতি
| বিষয় | অবস্থা | মন্তব্য |
|---|---|---|
| সব টেবিলে Row Level Security | ✅ | Supabase advisor-এ RLS-এর অভাবের কোনো সতর্কতা আসেনি |
| Admin ও ক্রেতা আলাদা | ✅ | `admins` টেবিল + `is_admin()` |
| ক্রেতা শুধু নিজের অর্ডার দেখে | ⚠️ | নিয়ম আছে, লগইন না থাকায় এখনো ব্যবহারযোগ্য নয় |
| Client থেকে আসা দাম/role অবিশ্বাস | ✅ | `place_order` নিজে দাম হিসাব করে |
| ক্রেতার লগইন ও session | ❌ | ধাপ C, Supabase Auth ব্যবহার হবে (নিজে পাসওয়ার্ড রাখা হবে না) |

## অর্ডার ও stock
| বিষয় | অবস্থা | মন্তব্য |
|---|---|---|
| Input যাচাই (সার্ভারে) | ✅ | ফোন, নাম, ঠিকানা, সংখ্যা |
| Overselling ঠেকানো | ❌ | stock কমে না ([4.database.md](4.database.md)) |
| ডুপ্লিকেট অর্ডার ঠেকানো | ❌ | idempotency key বাকি |
| Spam/অপব্যবহার সীমা | ❌ | `place_order` যে কেউ বারবার ডাকতে পারে। ভুয়া অর্ডারে ডেটা ভরে যেতে পারে। ধাপ E-তে ঠিক হবে |
| Audit trail | ❌ | কে status বদলাল তার লগ নেই |

## Secret ও কনফিগারেশন
| বিষয় | অবস্থা | মন্তব্য |
|---|---|---|
| Repo-তে শুধু publishable key | ✅ | `service_role`/secret key repo বা চ্যাটে নেই |
| Secret ব্যবহার করতে হলে | নিয়ম | শুধু Edge Function-এর environment secret হিসেবে |
| Key ফাঁস হলে | নিয়ম | সাথে সাথে Supabase dashboard থেকে rotate করা |

## Frontend
| বিষয় | অবস্থা | মন্তব্য |
|---|---|---|
| XSS | ⚠️ | পণ্যের নাম/বিবরণ `innerHTML`-এ বসে, escape করা নেই। এখন শুধু admin লিখতে পারে বলে ঝুঁকি কম, কিন্তু admin panel বানানোর আগে escape বা `textContent` ব্যবহার করতে হবে। অর্ডারের তথ্য (নাম, ঠিকানা) `esc()` দিয়ে দেখানো হয় |
| Security header (CSP ইত্যাদি) | ⚠️ | GitHub Pages-এ নিজে header বসানো যায় না। দরকার হলে Cloudflare ইত্যাদি সামনে রাখতে হবে |
| HTTPS | ⚠️ | Supabase ও GitHub Pages দুটোই HTTPS দেয়। নিজের domain হলে চালু আছে কি না দেখে নিন |

## Supabase security advisor (2026-10-28)
3টি সতর্কতা এসেছিল, সবই "SECURITY DEFINER function সবাই ডাকতে পারে":
- `place_order`: ইচ্ছাকৃত, কারণ ক্রেতা লগইন ছাড়াই অর্ডার করে।
- `is_admin`: দরকারি, কারণ RLS নিয়ম এটা ডাকে। শুধু true/false দেয়।
- `rls_auto_enable`: আমাদের বানানো নয়, Supabase-এর। কী করে জানা ও দরকার না হলে বন্ধ করার কথা ভাবা বাকি।

## ব্যক্তিগত তথ্য ও আইন
| বিষয় | অবস্থা |
|---|---|
| সংগৃহীত তথ্য | নাম, ফোন, ঠিকানা (অর্ডারে) |

| গোপনীয়তা নীতি ও শর্তাবলী পেজ | ❌ নেই |
| আইন ও ভোক্তা-সুরক্ষা প্রযোজ্যতা | যাচাই হয়নি। প্রযোজ্য নিয়মের জন্য একজন পেশাদারের পরামর্শ নিন |

## পেমেন্ট যোগ করার সময় অবশ্যই (ধাপ F)
- কার্ডের তথ্য নিজেদের সিস্টেমে বা লগে রাখা যাবে না। Gateway-র hosted পেজ ব্যবহার।
- ব্রাউজারে "সফল" পেজ দেখে অর্ডার নিশ্চিত করা যাবে না। Gateway-র সার্ভার থেকে আসা যাচাই করা বার্তাই (webhook বা verify API) সত্য।
- Webhook-এর signature যাচাই, ডুপ্লিকেট event ঠেকানো, বিলম্বে বা উল্টো ক্রমে আসা event সামলানো।
- Payment আর order status-এর বদল স্পষ্ট ও লগ করা।
- আগে sandbox, তারপর আসল।
