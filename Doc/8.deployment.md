# 8. Deployment ও Operations

## পরিবেশ
| পরিবেশ | অবস্থা |
|---|---|
| Production | Supabase project `gjawsgadcwqlohvfakzp` + GitHub repo `Joynulk/website` (`main`)। সাইট কোথায় চালু (যেমন GitHub Pages) সেটা এখানে যাচাই হয়নি |
| Staging | নেই। আসল ক্রেতা আসার আগে আলাদা Supabase project ও আলাদা branch দিয়ে বানানো উচিত (খরচ ও project সংখ্যার সীমা আপনার প্ল্যানে দেখে নিন) |

## Hosting
- Frontend শুধু static ফাইল, যেকোনো static hosting-এ চলে (GitHub Pages, Netlify, Cloudflare Pages)।
- আলাদা build দরকার নেই।
- নিজের domain নিলে HTTPS চালু আছে কি না দেখে নিন।

## Branch ও পরিবর্তন
- `main` = যা সাইটে চলে। সরাসরি `main`-এ push চলবে ছোট ও নিরাপদ পরিবর্তনে।
- বড় বা ঝুঁকির পরিবর্তন আলাদা branch-এ করে সাইটে দেখে নিয়ে merge।
- Force-push, branch মোছা, history বদলানো আপনার স্পষ্ট অনুমতি ছাড়া হবে না।
- `.env`, key, secret কখনো commit নয়।

## Database পরিবর্তন
1. `supabase/migrations/NNN_নাম.sql` লিখুন (rollback SQL মন্তব্যে সহ)।
2. আগে staging বা ছোট ডেটায় চালান।
3. Production-এ প্রয়োগ।
4. Supabase security advisor দেখুন ([6.security.md](6.security.md))।
5. [7.testing.md](7.testing.md)-এর সংশ্লিষ্ট পরীক্ষা আবার চালান।

## Rollback
| কী | কীভাবে |
|---|---|
| Frontend | `git revert <commit>` তারপর push |
| Database | ওই migration-এর rollback SQL চালানো। ডেটা ধ্বংস হয় এমন পরিবর্তনের আগে backup নিন |

## Backup ও restore
- Supabase প্ল্যান অনুযায়ী backup-এর সুবিধা আলাদা। আপনার প্ল্যানে কী আছে (দৈনিক backup, point-in-time recovery) dashboard-এ দেখুন। এখানে যাচাই হয়নি।
- যা-ই থাকুক, restore একবার চালিয়ে দেখা না পর্যন্ত backup নির্ভরযোগ্য ধরা যাবে না।
- নিয়মিত `orders`, `order_items` export করে রাখার ব্যবস্থা ভাবুন (Table Editor থেকে CSV)।

## Monitoring
- Supabase dashboard-এর Logs (API, Postgres) ও Advisors।
- অর্ডার আসছে না বা error বাড়ছে কি না দেখতে সপ্তাহে একবার logs দেখা।
- পরে দরকার হলে error tracking যোগ।

## খরচের দিকে নজর
| কী | দেখার জায়গা |
|---|---|
| Supabase প্ল্যানের সীমা (storage, bandwidth, database আকার) | Dashboard -> Usage |
| SMS ও ইমেইল (ধাপ F) | প্রতি বার্তার খরচ ও মাসিক সীমা ঠিক করে নিন |
| পেমেন্ট gateway | প্রতি লেনদেনে চার্জ ও সেটআপ ফি |
| Domain | বার্ষিক নবায়ন |
